# Getting Support

Thank you for using AI Gateway. Here's how to get help, ranked from fastest to most thorough.

## 1. Read the docs

Most questions are answered in:

- [README](README.md) — overview and quickstart
- [`docs/getting-started.md`](docs/getting-started.md) — install, configure, first request
- [`docs/configuration.md`](docs/configuration.md) — environment variables, model overrides
- [`docs/api-reference.md`](docs/api-reference.md) — endpoint contract
- [`docs/faq.md`](docs/faq.md) — common gotchas

## 2. Search existing conversations

Before opening a new thread, search:

- [Issues](../../issues?q=is%3Aissue) — open and closed
- [Discussions](../../discussions) — Q&A, ideas, show & tell

## 3. Ask in Discussions

For questions that aren't bugs:

- [Q&A](../../discussions/categories/q-a) — usage, configuration, "is this possible?"
- [Ideas](../../discussions/categories/ideas) — proposals and design discussions
- [Show & tell](../../discussions/categories/show-and-tell) — share what you built

## 4. Open an issue

If you've hit a bug or want to propose a concrete feature, [open an issue](../../issues/new/choose) and pick the right template.

A great bug report includes:

- AI Gateway commit SHA or version
- .NET SDK version (`dotnet --version`)
- OS and architecture
- The request body that triggers the bug
- The full error (logs from `dotnet run`, stack trace, status code)
- The provider(s) you have configured

## 5. Security issues

**Do not** open a public issue. Follow the process in [SECURITY.md](SECURITY.md).

## Response expectations

This is an open-source project maintained by volunteers. We aim to acknowledge issues within a week, but there is no SLA. Pull requests are the fastest path to a fix — see [CONTRIBUTING.md](CONTRIBUTING.md).
